import { Card, CardGrid } from '@astrojs/starlight/components';

```console
$ cargo install carmy-cli
$ carmy new shop && cd shop
$ cargo run           # HTTP
$ cargo run -- mcp    # as mesmas tools via MCP
```

<CardGrid>
  <Card title="Tools tipadas" icon="puzzle">
    Uma `async fn` com `#[carmy::tool]` vira uma tool. Os JSON Schemas de entrada e saída
    são derivados dos seus tipos, então os agentes a descobrem sem ler documentação.
  </Card>
  <Card title="Efeitos explícitos" icon="warning">
    Toda tool declara `none`, `read`, `write`, `external_write` ou `destructive`.
    Tools destrutivas exigem uma confirmação confiável antes de rodar.
  </Card>
  <Card title="Retries seguros" icon="random">
    Agentes repetem chamadas depois de timeouts. Um `request_id` repetido devolve o
    resultado já registrado. O efeito colateral nunca roda duas vezes.
  </Card>
  <Card title="Erros para máquinas" icon="document">
    Os erros trazem um código estável, uma categoria, `recoverable`, `retryable`,
    `retry_after` e uma `suggested_action`, e não apenas "Algo deu errado".
  </Card>
  <Card title="Streaming e cancelamento" icon="rocket">
    Um stream de eventos do runtime (servido como SSE via HTTP), prazos de execução e
    cancelamento propagado a partir de desconexões do cliente e do MCP.
  </Card>
  <Card title="Um runtime, vários transportes" icon="setting">
    HTTP e MCP são adaptadores finos sobre o mesmo runtime e o mesmo código das tools. O
    core não conhece nenhum dos dois.
  </Card>
</CardGrid>
